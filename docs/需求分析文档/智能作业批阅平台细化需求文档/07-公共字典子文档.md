## 1. 系统字典设计

根据 CLAUDE.md 规范，系统字典采用统一的数据字典表进行管理。

### 1.1 字典表结构

```sql
CREATE TABLE TB_S_DICT (
    ID VARCHAR(32) NOT NULL PRIMARY KEY COMMENT '主键（雪花 ID）',
    DICT_TYPE VARCHAR(50) NOT NULL COMMENT '字典类型',
    DICT_LABEL VARCHAR(100) NOT NULL COMMENT '字典标签',
    DICT_VALUE VARCHAR(50) NOT NULL COMMENT '字典值',
    DICT_SORT INT DEFAULT 0 COMMENT '排序',
    REMARK VARCHAR(200) COMMENT '备注',
    STATUS VARCHAR(10) DEFAULT '1' COMMENT '状态（1：正常 0：停用）',
    CJR VARCHAR(32) COMMENT '创建人',
    CJSJ DATETIME COMMENT '创建时间',
    GXR VARCHAR(32) COMMENT '更新人',
    GXSJ DATETIME COMMENT '更新时间',
    LJSC INT DEFAULT 0 COMMENT '逻辑删除（0：显示，1：隐藏）',
    INDEX IDX_TYPE (DICT_TYPE),
    UNIQUE KEY UK_TYPE_VALUE (DICT_TYPE, DICT_VALUE)
) COMMENT='系统字典表';
```

### 1.2 字典类型清单

## 3. 编码规则

### 3.1 题目编号生成规则

**格式**：`SUBJ-YYYY-NNNNNN`（共 12 位）

| 组成部分 | 位数 | 说明 | 示例 |
|---------|------|------|------|
| SUBJ | 4 位 | 学科代码 | CHIN=语文，MATH=数学 |
| YYYY | 4 位 | 年份 | 2026 |
| NNNNNN | 6 位 | 流水序号 | 000001 |

**示例**：
- `MATH-2026-000001` = 数学/2026 年/第 1 题
- `CHIN-2026-000123` = 语文/2026 年/第 123 题

### 3.2 试卷编号生成规则

**格式**：`PAPER-SUBJ-YYYY-NNNN`（共 16 位）

| 组成部分 | 位数 | 说明 | 示例 |
|---------|------|------|------|
| PAPER | 5 位 | 固定前缀 | PAPER |
| SUBJ | 4 位 | 学科代码 | MATH |
| YYYY | 4 位 | 年份 | 2026 |
| NNNN | 4 位 | 流水序号 | 0001 |

**示例**：
- `PAPER-MATH-2026-0001` = 数学/2026 年/第 1 套试卷

### 3.3 作业编号生成规则

**格式**：`HW-YYYYMMDD-NNNN`（共 16 位）

| 组成部分 | 位数 | 说明 | 示例 |
|---------|------|------|------|
| HW | 2 位 | 固定前缀 | HW |
| YYYYMMDD | 8 位 | 布置日期 | 20260331 |
| NNNN | 4 位 | 流水序号 | 0001 |

**示例**：
- `HW-20260331-0001` = 2026 年 03 月 31 日/第 1 个作业

### 3.4 学生学号编码规则

**格式**：`SCH-GRADE-CLASS-NNN`（共 14 位）

| 组成部分 | 位数 | 说明 | 示例 |
|---------|------|------|------|
| SCH | 3 位 | 学校代码 | 001 |
| GRADE | 2 位 | 年级代码 | 03（三年级） |
| CLASS | 2 位 | 班级代码 | 01（一班） |
| NNN | 3 位 | 班内序号 | 001 |

**示例**：
- `001-03-01-001` = 001 学校/三年级/一班/001 号

### 3.5 教师工号编码规则

**格式**：`TCH-SCH-NNNN`（共 10 位）

| 组成部分 | 位数 | 说明 | 示例 |
|---------|------|------|------|
| TCH | 3 位 | 固定前缀 | TCH |
| SCH | 3 位 | 学校代码 | 001 |
| NNNN | 4 位 | 流水序号 | 0001 |

**示例**：
- `TCH-001-0001` = 001 学校/第 0001 号教师

## 4. 术语解释

| 术语 | 解释 |
|------|------|
| AI 批阅 | 利用人工智能技术对作业进行自动批改，包含客观题判分和主观题批改 |
| 置信度 | AI 对判分结果的自信程度，取值范围 0-1，<0.7 标记待复核 |
| 校本资源 | 学校自有的教学资源，包含题库、试卷等，支持校本私有和区域共享两种模式 |
| 错题再练 | 基于错题数据的个性化巩固练习，系统智能推荐相似题目 |
| 数据驾驶舱 | 数据可视化大屏，支持多维度作业数据分析展示 |
| 学情报告 | 基于作业数据的分析报告，包含班级报告和个人报告两种类型 |
| 知识点 | 学科教学中的知识单元，支持树形层级结构管理 |
| 讲评 | 教师基于作业数据开展的课堂教学活动，包含重点讲评、错题讲评、互动讲评等模式 |
| 相似度 | 题目之间的相似程度，基于知识点、难度、题型等维度计算 |
| 掌握状态 | 学生对错题知识点的掌握程度，分为未掌握、待巩固、已掌握三个等级 |

## 6. 补充说明

### 6.1 字典扩展

当需要新增字典类型或字典值时，按照以下流程：
1. 在 TB_S_DICT 表中插入新记录
2. 更新本文档
3. 通知相关开发人员

### 6.2 字典值变更影响评估流程

**影响评估检查清单**：

| 检查项 | 检查内容 | 检查方式 |
|--------|---------|---------|
| 数据库依赖 | 哪些表的哪些字段使用了该字典值 | 查询表结构注释、ER 图 |
| 代码依赖 | 哪些代码模块引用了该字典值 | 全局搜索字典值 |
| 接口依赖 | API 接口文档中是否使用该字典值 | 检查 API 文档 |
| 前端依赖 | 前端代码中是否有硬编码 | 搜索前端代码 |
| 测试依赖 | 测试用例中是否涉及该字典值 | 检查测试用例 |
| 外部依赖 | 外部系统是否依赖该字典值 | 检查集成接口 |

**变更风险等级**：

| 风险等级 | 说明 | 处理方式 |
|---------|------|---------|
| 高风险 | 核心业务字典值，大量引用 | 需充分测试，分阶段上线 |
| 中风险 | 部分功能使用 | 回归测试相关功能 |
| 低风险 | 新增字典值或很少使用 | 常规测试即可 |

**字典值停用规范**：
- 已使用的字典值不允许直接删除，只能设置为停用状态（STATUS=0）
- 停用的字典值在前端下拉列表中不显示，但历史数据仍可正常展示
- 如确需删除，需先完成数据迁移，确保无引用后再执行
