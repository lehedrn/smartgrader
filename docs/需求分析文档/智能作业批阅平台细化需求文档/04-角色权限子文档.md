## 1. 角色体系设计

### 1.1 角色定义

根据 CLAUDE.md 规范，本系统采用包名 `com.linewell.*`，角色权限设计与系统用户管理模块关联。

| 角色 ID | 角色名称 | 角色描述 | 用户群体 | 访问端 |
|--------|---------|---------|---------|--------|
| R01 | 学生 | 查看作业、提交答案、查看批阅结果、错题练习 | 在校学生 | 移动端 H5 |
| R02 | 教师 | 布置作业、批阅作业、讲评、查看报告、使用资源库 | 任课教师 | PC 端 + 移动端 |
| R03 | 家长 | 查看孩子作业报告和学情数据 | 学生家长 | 移动端 H5 |
| R04 | 学校管理者 | 查看全校作业数据驾驶舱、学情分析 | 校长/教务主任 | PC 端 |
| R05 | 系统管理员 | 管理基础配置、用户、权限等 | IT 运维人员 | PC 端 |

## 3. 数据权限设计

### 3.1 数据权限规则

| 角色 | 数据范围 | 规则说明 |
|------|---------|---------|
| R01 学生 | 个人数据 | 只能查看和操作自己的作业、提交、批阅、报告数据 |
| R02 教师 | 任教班级数据 | 可查看所教班级的所有学生作业数据 |
| R03 家长 | 绑定孩子数据 | 仅可查看绑定孩子的作业报告数据 |
| R04 学校管理者 | 全校数据 | 可查看全校所有作业数据 |
| R05 系统管理员 | 全部数据 | 可查看和操作所有数据 |

### 3.2 数据权限实现

#### 学生数据过滤

```sql
-- R01 学生：只能查看自己的作业
SELECT * FROM TB_B_HOMEWORK_PUBLISH 
WHERE ID IN (
    SELECT HOMEWORK_ID FROM TB_B_HOMEWORK_SUBMIT 
    WHERE STUDENT_ID = #{currentUserId}
)

-- 查看自己的提交记录
SELECT * FROM TB_B_HOMEWORK_SUBMIT 
WHERE STUDENT_ID = #{currentUserId}

-- 查看自己的批阅记录
SELECT * FROM TB_B_HOMEWORK_GRADE 
WHERE SUBMIT_ID IN (
    SELECT ID FROM TB_B_HOMEWORK_SUBMIT 
    WHERE STUDENT_ID = #{currentUserId}
)
```

#### 教师数据过滤

```sql
-- R02 教师：查看所教班级的作业
SELECT DISTINCT hp.* FROM TB_B_HOMEWORK_PUBLISH hp
INNER JOIN TB_S_TEACHER_CLASS tc ON hp.CLASS_ID = tc.CLASS_ID
WHERE tc.TEACHER_ID = #{currentUserId}

-- 查看所教班级学生的提交
SELECT hs.* FROM TB_B_HOMEWORK_SUBMIT hs
INNER JOIN TB_S_STUDENT_CLASS sc ON hs.STUDENT_ID = sc.STUDENT_ID
INNER JOIN TB_S_TEACHER_CLASS tc ON sc.CLASS_ID = tc.CLASS_ID
WHERE tc.TEACHER_ID = #{currentUserId}
```

#### 家长数据过滤

```sql
-- R03 家长：查看绑定孩子的报告
SELECT hr.* FROM TB_B_REPORT_STUDENT hr
INNER JOIN TB_S_PARENT_STUDENT ps ON hr.STUDENT_ID = ps.STUDENT_ID
WHERE ps.PARENT_ID = #{currentUserId}
```

#### 管理者数据过滤

```sql
-- R04 学校管理者：查看全校数据
SELECT * FROM TB_B_HOMEWORK_PUBLISH 
WHERE SCHOOL_ID = #{currentUserSchoolId}
```

## 4. 特殊权限规则

### 4.1 个人数据仅自己可维护

| 规则 | 说明 |
|------|------|
| 适用场景 | 学生修改自己的作业提交（如撤回重新提交） |
| 实现方式 | 校验 STUDENT_ID 是否为当前用户 |
| 例外 | 教师可要求学生重新提交，系统管理员可操作所有数据 |

### 4.2 教师查看任教班级数据

| 规则 | 说明 |
|------|------|
| 适用场景 | 教师查看作业、批阅、报告等数据 |
| 权限范围 | 仅可查看所教班级的数据 |
| 实现方式 | 通过 TB_S_TEACHER_CLASS 表关联过滤 |

### 4.3 家长绑定孩子查看报告

| 规则 | 说明 |
|------|------|
| 适用场景 | 家长查看孩子作业报告 |
| 权限范围 | 仅可查看绑定孩子的报告 |
| 绑定关系 | 一个家长可绑定多个孩子，一个孩子可被多个家长绑定 |
| 实现方式 | 通过 TB_S_PARENT_STUDENT 表关联过滤 |

### 4.4 批阅权限

| 规则 | 说明 |
|------|------|
| 适用场景 | 教师批阅作业 |
| 权限条件 | 教师必须是所教班级的任课教师 |
| 修改评分 | 教师可修改 AI 给出的评分，但需保留修改痕迹 |
| 实现方式 | 校验教师与班级的关联关系 |

## 5. 权限校验实现

### 5.1 前端权限控制

```javascript
// 菜单权限控制（Vue Router）
const menuPermission = {
  '/homework/publish': ['R02', 'R05'],      // 作业发布：教师、管理员
  '/homework/grade': ['R02', 'R05'],        // 作业批阅：教师、管理员
  '/homework/submit': ['R01', 'R05'],       // 作业提交：学生、管理员
  '/resource/question': ['R02', 'R05'],     // 题库管理：教师、管理员
  '/report/class': ['R02', 'R04', 'R05'],   // 班级报告：教师、管理者、管理员
  '/report/personal': ['R01', 'R02', 'R03', 'R05'], // 个人报告：全部
  '/cockpit': ['R04', 'R05'],               // 驾驶舱：管理者、管理员
  '/admin': ['R05']                         // 系统管理：仅管理员
}

// 按钮权限控制
const buttonPermission = {
  'homework:publish:create': ['R02', 'R05'],
  'homework:publish:update': ['R02', 'R05'],
  'homework:publish:delete': ['R02', 'R05'],
  'homework:grade:update': ['R02', 'R05'],
  'homework:grade:confirm': ['R02', 'R05'],
  'resource:question:create': ['R02', 'R05'],
  'report:export': ['R01', 'R02', 'R03', 'R04', 'R05']
}

// 权限判断函数
function hasPermission(permission) {
  const userRole = store.getters.userRole
  const permissions = rolePermissions[userRole] || []
  return permissions.includes('*') || permissions.includes(permission)
}
```

```java
// 数据权限 AOP
@DataScope(tableAlias = "hp", deptAlias = "class_id", userAlias = "create_user")
public List<HomeworkPublish> selectList(HomeworkQuery query) {
    return homeworkMapper.selectList(query);
}

// 权限拦截器
@Component
public class DataPermissionInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, 
                            HttpServletResponse response, 
                            Object handler) {
        // 获取当前用户角色
        String role = SecurityContextHolder.getContext()
            .getAuthentication().getAuthorities().toString();
        
        // 根据角色设置数据过滤条件
        DataScope scope = getDataScopeByRole(role);
        DataScopeContext.set(scope);
        
        return true;
    }
}
```

| 操作 | 审计级别 | 说明 |
|------|---------|------|

| 删除作业 | 高 | 记录删除人、删除时间、作业信息 |
| 导出报告 | 中 | 记录导出人、导出时间、报告类型 |

### 7.3 审计日志表结构

```sql
CREATE TABLE TB_B_AUDIT_LOG (
    ID VARCHAR(32) NOT NULL PRIMARY KEY,
    USER_ID VARCHAR(32),           -- 操作用户 ID
    USER_NAME VARCHAR(100),        -- 操作用户名
    OPERATION VARCHAR(100),        -- 操作类型
    MODULE VARCHAR(50),            -- 模块
    TARGET_ID VARCHAR(32),         -- 操作对象 ID
    TARGET_TYPE VARCHAR(50),       -- 操作对象类型
    CONTENT TEXT,                  -- 操作内容（JSON）
    RESULT VARCHAR(20),            -- 操作结果（SUCCESS/FAIL）
    IP VARCHAR(50),                -- 操作 IP
    DEVICE VARCHAR(100),           -- 操作设备
    CREATE_TIME DATETIME,          -- 操作时间
    INDEX IDX_USER_TIME (USER_ID, CREATE_TIME),
    INDEX IDX_MODULE_TIME (MODULE, CREATE_TIME)
) COMMENT='审计日志表';
```
